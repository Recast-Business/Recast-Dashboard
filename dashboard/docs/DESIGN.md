# Recast Dashboard — Design System

> **Read this before adding any new UI.** Every new component, every
> new page should reach for these tokens and recipes first. The whole
> point of the Phase L pass was to stop reinventing buttons.
>
> This document mirrors the canonical Recast Design System summary
> (`/tmp/recast-system-v2.html`, generated by Anthropic Claude Design,
> May 2026). When the two disagree, the design summary wins.

## 0. Brand anatomy

### Mark

`<img src="/recast-mark.svg">` · 28×28 · 4px radius · 3 colours: black
ground, white outline, Electric Blue R. **Never redrawn.** A redrawn
mark is a brand violation.

### Wordmark

```
font-display font-extrabold uppercase   letter-spacing: 0.08em
```

`0.08em` tracking lives on the wordmark **only**. Headlines tighten to
`-0.02em` (the canonical display tracking).

## 2. Component recipes

### Card (default surface)

```tsx
<div className="rounded-lg border border-white/8 bg-ash p-tile-md shadow-none">
```

**Hairline border carries elevation, never shadow.** `shadow-*` is
banned outside of transient surfaces (Popover, DropdownMenu, Toast).

The shadcn `<Card>` primitive resolves `bg-card` to `ash` (`#111`) in
dark mode; the `border` semantic becomes the canonical `border-white/8`
hairline. Just stick to the shadcn `<Card>` component and it does the
right thing.

### KPI tile

> *Eyebrow caps + delta chip on top, display-weight value, sparkline +
> meta on the foot. **Status accent rule on top-edge for non-neutral
> KPIs.***

```tsx
<div className="rounded-lg border bg-card p-tile-md hover:bg-[#131313]">
  <div className="flex items-center justify-between">
    <span className="inline-flex items-center gap-1.5 text-eyebrow text-steel">
      <ArrowDownLeft className="h-3.5 w-3.5" />
      INFLOW · MTD
    </span>
    <span className="rounded-sm bg-paid-tint px-1.5 py-0.5 text-eyebrow text-paid">
      +12.4%
    </span>
  </div>
  <div className="mt-2 font-display text-display font-extrabold tabular tracking-[-0.022em]">
    $118,420
  </div>
  <Sparkline values={…} tone="paid" className="mt-2" />
  <div className="mt-1 text-small text-steel">vs $105,400 Jun</div>
</div>
```

**Non-neutral tone** (Outstanding tile when overdue, etc.) renders as a
**top-edge rule**, not a full border accent:

```tsx
className="border-t-2 border-t-partial"   // amber for warning
className="border-t-2 border-t-overdue"   // red for danger
```

### Status pill

```tsx
<span className="inline-flex items-center gap-1.5 rounded-sm bg-paid-tint px-2 py-0.5 text-eyebrow text-paid">
  <span className="h-1.5 w-1.5 rounded-full bg-current" />
  PAID
</span>
```

Bullet dot is `bg-current` so it always matches the text colour. Swap
the colour token for `partial / overdue / unpaid`. **Never invent a
fifth status.** If the data model needs more states, the status enum
must change first (DB → types → UI), not the colour palette.

### Eyebrow label

Bare metadata (default — used above numbers and KPI labels):

```tsx
<span className="text-eyebrow uppercase text-steel">Inflow this month</span>
```

Section header (used on the design system summary itself, and anywhere
the eyebrow needs to anchor a major section):

```tsx
<span className="inline-flex items-center gap-2 text-eyebrow uppercase text-steel
                 before:block before:h-px before:w-6 before:bg-electric">
  Tailwind palette
</span>
```

The `<EyebrowLabel withRule>` prop renders the second form.

### Money cell (always tabular)

```tsx
<span className="font-display font-bold tabular tracking-[-0.022em]">
  $118,420
</span>
```

Always `.tabular`. Always include the dollar sign inside the cell —
the column header should not say "($)". The `<MoneyCell amount={…}>`
primitive handles split decimals (`.00` rendered smaller and
steel-coloured) at display + h2 sizes.

### Invoice cell (the cell-is-the-invoice grid)

```tsx
<button className="block w-full rounded-sm border border-rule border-l-2 p-2 text-left
                   transition-colors duration-base ease-out
                   hover:bg-white/[0.04]
                   focus-visible:ring-2 focus-visible:ring-electric">
  <div className="tabular text-body">$28,400</div>
  <div className="text-eyebrow text-steel">INV-0362</div>
</button>
```

Each cell is a button — clicking it opens the invoice. Status is
communicated by the cell's left border colour:

```tsx
className={cn(
  "border-l-2",
  status === "paid" && "border-l-paid",
  status === "partial" && "border-l-partial",
  status === "overdue" && "border-l-overdue",
  status === "unpaid" && "border-l-unpaid",
)}
```

### Table row — Attio-style soft hover

```tsx
<tr className="border-b border-rule transition-colors duration-base ease-out
               hover:bg-white/[0.04]">
  …
</tr>
```

12px vertical padding · row hover `rgba(255,255,255,0.04)`. Money is
right-aligned and tabular. Actions (Edit, Delete icon buttons) hide
until row hover.

Every grid that scrolls horizontally **must** sticky-left the first
column (creator name, vendor name) using:

```css
position: sticky; left: 0; z-index: 1; background: #0d0d0d;
```

Without it the user loses context mid-scroll.

## 3. Notes & flags for the engineer

These are direct from the canonical design system summary.

1. **Brand pass tokens are unchanged.** `--primary` stays `#2563EB`,
   `--ring` still matches, `font-display` stays Unbounded. This system
   layers — it does not re-derive.

2. **Chart colours are explicit.**
   - Inflow: `#2563EB` with a `#3B82F6` top-stop on the bar gradient
   - Outflow: solid `#3a3f4b`
   - Prior-year overlay: same colours at 55% opacity, `stroke-dasharray="3 4"`
   - **Don't fall back to Recharts defaults.**

3. **Status enum is fixed.** Cell tints in the talent grid use `rgba()`
   at 5–7% alpha, with a 6×6 px corner pip for redundancy in case the
   tint is too subtle on the engineer's monitor. Do not change the
   four-state vocabulary.

4. **Sticky-left creator column.** The grid uses `position: sticky;
   left: 0; z-index: 1; background: #0d0d0d`. If you wrap the grid in
   a virtualised list, sticky needs the parent to be the scroll
   container.

5. **Sidebar collapsed rail.** 64px mode hides the wordmark and section
   titles; the R-mark stays at 28px square and items become 32px icon
   buttons. Same active-state treatment (rgba blue 12% bg + blue icon).

6. **Reconciliation strip.** The 4th cell ("Outstanding") gets a tinted
   blue background `rgba(37, 99, 235, 0.06)` and the value uses the
   30px display weight. The other three cells are 22px.

7. **Vendor side panel.** 320px column at desktop, drops below the main
   column < 1100px. Recent receipts cap at 5 with "All" link; **Danger-
   zone Delete is the only place a destructive button lives in red —
   every other delete is a quiet icon.**

8. **No emoji, no gradients (except the 2-stop blue bar fill), no glow
   / glass / drop shadows. Hover states are colour-only.**

9. **Schema preserved.** Designs assume one-invoice-per-(creator, year,
   month), separate ad-hoc on vendors, `rent_groups` vs. residents
   distinction. No restructures.

## 4. When to add new UI — decision tree

```
Need a new visual element?
├── Is it a status / state? → Use status enum + status pill recipe.
│                              If the enum doesn't cover it, extend
│                              the DB enum first, then add the colour.
├── Is it a number? → Use money cell or KPI tile recipe + .tabular.
├── Is it a surface (card, panel, dialog)? → Card recipe.
│                                            Hairline border, no shadow.
├── Is it a navigation affordance? → Sidebar nav item or DropdownMenu.
└── Genuinely new? → Sketch it in the same vocabulary as the recipes
                    above. Open dashboard/docs/DESIGN.md and add it
                    here in the same commit.
```

If none of the above answer the question, stop and ask. The system is
small on purpose — every new primitive is a tax on the next dev who
opens this file.
